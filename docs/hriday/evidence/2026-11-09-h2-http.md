# H2.4a HTTP and API bootstrap evidence

Date: 9 November 2026 IST. Branch: Hriday. Source: original endpoints 2/3/4/7/8/30/31, F1 and section 12. DTO fields/schema, provider choice and Ishaan-owned implementation remain unchanged.

Wired seven core endpoints with generated OpenAPI and exact public/private ownership. Creation uses HTTP 201 and the source two-ID response. Capture accepts no body or an empty object, then returns OrderSummary; extra body fields cannot redirect context. Private responses use the existing role-specific read layer. The actual API bootstrap composes database credentials, sandbox checkout factory, stores, read service, existing intelligence export and pg-boss lifecycle before listening. Health reports H2/stub.

- PASS: pnpm test:db — 102 PostgreSQL/HTTP cases, including eight new route cases. Real database, queue, credentials, client, parsers and API validation/serialization run with only synthetic sandbox HTTP responses injected.
- PASS: pnpm test — 161 offline cases; all 102 database cases explicitly skipped. PASS: pnpm typecheck and pnpm lint; final formatting checked before commit.
- PASS: actual API process booted on temporary loopback port 3112 using the existing development database. Queue/database readiness, H2/stub health, all seven OpenAPI routes and private-route 401 were observed over TCP. The smoke process was stopped afterward; no external PayPal call was made.

The eight HTTP cases cover generated docs/readiness; public config/create/bodyless capture and minimal result; authenticated buyer capture/history; merchant list/detail tenant scope; anonymous/wrong-role/foreign-buyer/tampered-token denials; request/query/path validation before vendor calls; disallowed checkout roles and safe vendor/setup errors; stable pagination/foreign cursor rejection.

Initial checks found three valid bodyless capture requests returning 400 because Fastify treated an optional object body schema as requiring a body. The route now uses explicit safe Zod pre-validation for optional empty input and documents no body, matching the source. All 102 checks subsequently passed. A repeated local PostgreSQL interruption initially prevented suite setup; restarting the same ignored cluster with the original pg_ctl command restored the checks without resetting data or changing the installed service.
