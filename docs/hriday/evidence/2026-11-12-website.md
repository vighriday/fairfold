## Issues found and repaired

- The browser-native fetch function required its global receiver. The production client now calls it through a wrapper; a regression checks the receiver.
- Static page/asset loads exhausted the shared API request budget during realistic navigation. Only explicit public website routes are exempted. A regression serves 65 assets, then proves the 60-request API limit still returns 429 on the next API call. Upload limits remain intact.
- The supplied console's mobile active-tab scrolling and dock auto-fold were initially lost when replacing simulated logic. Both are restored and observed in Chromium. Signal state colours now follow the actual band.
- The initial order-list binding used the wrong path; it now uses `/api/merchant/orders`. Selected packing navigation preserves the actual selected order ID.
- Fastify matches the decoded legacy console filename; its redirect now registers the decoded path and passes the encoded-URL regression.
- A new runtime requires built public assets. Normal development and test commands build those assets first. Runtime startup fails if deployment omitted them, rather than serving a broken shell.

An earlier whole-suite run caught the legacy redirect failure. After the fix, the focused suite and the final complete offline run both passed. No earlier failed check is presented as the final result.
